ABSTRACT VARIANTS - "A Wakeup, Not a Broker"
Panel of 3 independent drafts (over the iac board) + the synthesis that was applied.
Style target: single spaced hyphen ( - ), no em/en dashes. All ~180w.
Date: 2026-07-05.

============================================================
CANDIDATE A - worker2 (~185w)
============================================================
Coordinating several LLM agents on one machine is treated as a messaging problem - reach for a queue, a broker, or an inter-agent protocol. This misreads the constraint. An LLM agent is a slow, serial consumer: one message per turn, seconds per turn, no parallelism. And between turns it is not a running process at all - no thread, no socket, nothing to deliver to. So the scarce primitive is not throughput but a wakeup: a way to rouse a dormant agent. The one wakeup a stateless agent can get is the return of a blocking receive parked in a cheap child process, which its harness re-invokes on exit - one activation per message, not per poll. Grant that, and the transport collapses to an append-only log plus a file lock: the commit log a broker is built on, minus the service. We present iac, a dependency-free C99 implementation (about 800 lines, one binary), give the token-cost model that moves the poll out of the model and into C, and report a fleet of agents that used iac to build iac. Nothing here is new but the participant - an agent, woken only by a returning process - and the discipline of giving it no more than it needs: a wakeup, not a broker.

CANDIDATE C - dev (~180w)
============================================================
Multi-agent coordination on one host is treated as a messaging problem and handed to a queue, a bus, or an inter-agent protocol. That answers the wrong question. Moving bytes between processes was solved decades ago; the hard part is waking a reader that, between turns, is not a running process at all - an LLM agent has no thread, no socket, no event loop for a message to land on. It is slow and serial besides, one message per turn at seconds per turn, so throughput, the thing a broker exists to manage, never binds. The scarce primitive is a wakeup, and the only one a stateless agent can receive is the return of a blocking recv parked in a cheap child process the harness re-invokes on exit: one model activation per message, not per poll. Grant that, and the transport collapses to an append-only log under a file lock - the commit log a broker is built on, minus the service. We present iac, a dependency-free C99 board (about 800 lines, one binary, no heap), the token-cost model that moves the poll from the model into C, and a fleet of agents that used the board to build the board. None of the parts are new; only the participant is - an agent woken by nothing but a returning process - and the discipline of giving it exactly that.
